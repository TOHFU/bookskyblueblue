## 📋 人間中心設計（HCD）プロセス改善レポート

### 1. 利用状況の把握（Before）
- `npm run dev` を起動したまま、Playwright（`scripts/hcd-explore.mjs`）で「検索 → 詳細 → TOPへ戻る」の操作を再度自動実行し、スクリーンショットを比較した。
- TOPへ戻った直後のスクリーンショット（`05-top-after.png`）で、保存済み作品0件時の空状態カード（`TopEmptyState`）が**半透明のゴースト状態**で写っていることを発見した。
- 原因: `TopScreen` は IndexedDB からの読み込み完了（`isLoading` が `false` になった瞬間）に `top-content-fadein`（`animation: fadeIn 0.4s`）というクラスをコンテンツ領域に付与しており、スピナー消滅と同時に0.4秒かけて不透明度0→1へフェードインする実装だった。読み込み完了の瞬間にユーザーが画面を見ると、コンテンツが薄く透けて見える「表示崩れ」のように見える時間帯が生じていた。

### 2. ユーザー要求事項
1. **R1**: TOP画面の読み込み完了直後、コンテンツ（空状態カードまたは作品一覧）が中途半端な不透明度で表示される時間を作らないこと。
2. **R2**: 既存のローディングスピナー表示（読み込み中のフィードバック）は維持すること。

### 3. 設計による解決策（実装内容）
- まず `.top-content-fadein` のアニメーション時間を `0.4s → 0.15s` に短縮したが、再検証したところ依然としてゴースト状態がスクリーンショットに写ることを確認した（フェーズ4で不合格 → フェーズ3へ再戻り）。
- スピナーで読み込み中を明示している以上、読み込み完了後の表示切り替えに追加のフェードインは不要と判断し、`TopScreen.tsx` から `top-content-fadein` クラスの付与自体を削除。`globals.css` の該当ルールも削除し（`fadeIn` キーフレーム自体は `.book-content-fadein` が使用しているため維持）、読み込み完了後は即時に不透明で表示するようにした。

### 4. 設計の評価結果（After）
- 単体テスト148件・型チェック・ESLintはすべて成功。
- ブラウザ再検証: `05-top-after.png` でTOP画面の空状態カードが完全に不透明で表示されることを確認 → **R1 合格**。
- 読み込み中は `LoadingSpinner`（「保存済み作品を読み込み中」）が変わらず表示される → **R2 合格**。
- 併せて実施した自動計測（検索キャッシュ再検索・詳細遷移）は今回の変更後は基準値内（`issues: []`）だった。
