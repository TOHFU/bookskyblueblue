## 📋 人間中心設計（HCD）プロセス改善レポート

### 1. 利用状況の把握（Before）
- サイクル14で見つけた「SearchDetailScreenのHydration警告」は、原因調査の結果Chakra UI(Emotion)のSSR/クライアント間クラス名生成順序に起因する可能性が高く、実害（表示崩れ）が確認できず、修正には styles/SSR設定という広範囲・高リスクな変更が必要になるため、今回は対応を見送り継続観察とした（無理に手を入れず安全側に倒す判断）。
- 代わりにダウンロード画面（`DownloadScreen`）のレイアウトを新規調査した。同画面は他の全画面（TOP/検索/詳細/読書）が `w="full"` かつ `minH="100svh"` のレスポンシブレイアウトである一方、**`w="375px"` / `minH="770px"` という固定ピクセル値**でハードコードされていた。
- ビューポート幅390px（一般的なiPhone）と430px（iPhone Pro Max等の大画面機）でスクリーンショットを比較したところ、430px幅では進捗バー・メッセージが画面中央に偏って表示され、左右に不自然な余白ができることを確認した。ビューポート幅が375pxより大きい端末（現行の主要スマートフォンの大半）で、他画面と比べて明らかに見た目が異なる・崩れて見える状態だった。

### 2. ユーザー要求事項
1. **R1**: ダウンロード画面のレイアウトが、他の画面と同様にビューポート幅に追従してレスポンシブに表示されること。
2. **R2**: 既存のダウンロード進捗表示・エラーメッセージ表示のロジックは変更しないこと。

### 3. 設計による解決策（実装内容）
- `src/components/screens/DownloadScreen/DownloadScreen.tsx` の最外周 `Box` を `w="375px" / minH="770px" / mx="auto"` の固定値から、他画面と同じ `w="full" / minH="100svh"` に変更した。

### 4. 設計の評価結果（After）
- 単体テスト148件・型チェック・ESLintすべて成功。
- ビューポート幅390px・430pxの両方でブラウザ再検証を行い、進捗バー・メッセージが画面幅に追従して表示されることを確認 → **R1 合格**。
- ダウンロード完了・エラー時のメッセージ表示ロジックは既存の単体テスト5件がすべて成功しており変更なし → **R2 合格**。
- レイアウト検証を再現できるよう `scripts/hcd-explore-download.mjs` を新規追加し、幅390px/430pxの2パターンでスクリーンショットを取得できるようにした。
