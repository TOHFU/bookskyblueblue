## 📋 人間中心設計（HCD）プロセス改善レポート

### 1. 利用状況の把握（Before）
- サイクル11で「検索結果カードが初回表示直後に見えなくなる」不具合を修正したはずだったが、Playwright（`scripts/hcd-explore.mjs`）を再実行して検証したところ、`03-search-results.png` で再びカードが**薄く透けた（半透明の）状態**でスクリーンショットに写っていることを確認した。
- 原因の再調査: サイクル11の修正は「画面内に既にある要素は `IntersectionObserver` の非同期通知を待たずに即時可視化する」ことのみを行っていたが、`FadeInBox` は可視化と同時に必ず `search-card-fadein` クラス（`opacity:0` から `0.3s` かけてフェードイン）を付与していたため、**即時可視化された要素であっても0.3秒のフェードインアニメーション自体は毎回発生**していた。結果として、タイミング次第でスクリーンショットがフェードインの途中（半透明）を捉えてしまう状態が残っていた。
- サイクル12でTOP画面についても同種の問題（読み込み完了直後のフェードインで半透明表示）を「フェード自体の廃止」で解決した実績があり、同じ考え方を検索結果カードにも適用していなかったことが今回の再発要因。

### 2. ユーザー要求事項
1. **R1**: 初回マウント時点で既に画面内にある検索結果カードは、フェードイン演出なしで即時に完全な不透明度で表示すること。
2. **R2**: スクロールにより画面外から新たに現れるカードには、これまでと同様にフェードイン演出（`fadeInDown`）を適用し続けること。

### 3. 設計による解決策（実装内容）
- `src/hooks/useIntersectionFadeIn.ts` に `shouldAnimate` フラグを追加。
  - マウント時点で画面内にある要素: `isVisible=true` のみ設定（`shouldAnimate` は `false` のまま）→ アニメーションなしで即時表示。
  - マウント時点で画面外の要素: `IntersectionObserver` が発火した時点で `isVisible` と `shouldAnimate` を同時に `true` にする → 従来通りフェードインしながら表示。
- `src/components/ui/FadeInBox/FadeInBox.tsx` を修正し、アニメーションクラスの付与を `isVisible` ではなく `shouldAnimate` に切り替え（不透明度の制御は `isVisible` のまま維持）。
- `src/hooks/useIntersectionFadeIn.test.tsx` を更新し、画面内マウント時は `shouldAnimate` が `false` のままであることを検証するアサーションを追加。

### 4. 設計の評価結果（After）
- 単体テスト148件・型チェック・ESLintすべて成功。
- ブラウザ再検証を2回連続で実行し、いずれも `03-search-results.png` で検索結果カード4件が完全な不透明度で即時表示されることを確認 → **R1 合格**。
- スクロールで追加読み込みされるカードのロジック（`IntersectionObserver` 経路 + `shouldAnimate` 付与）は変更しておらず、フェードイン演出は維持 → **R2 合格**。
