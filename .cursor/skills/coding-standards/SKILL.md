# コーディング規約

## 基本方針

GoogleのTypeScriptスタイルガイドをベースに、Reactプロジェクトに適したコーディング規約を定めます。

https://google.github.io/styleguide/tsguide.html

## 命名規則

- **変数名**: camelCase（例: `userName`）
- **関数名**: camelCase（例: `fetchData`）
- **クラス名**: PascalCase（例: `UserStore`）
- **インターフェース名**: PascalCase（例: `User`）
- **型エイリアス**: PascalCase（例: `UserID`）
- **定数**: UPPER_SNAKE_CASE（例: `API_URL`）

## ベストプラクティス
- **型安全**: 可能な限り型を明示し、`any` の使用は避ける
- **関数コンポーネント**: Reactの関数コンポーネントは常に関数形式で定義する
- **フックのルール**: フックはReactのルールに従い、トップレベルでのみ呼び出す
- **非同期処理**: `async/await` を使用し、Promiseチェーンは避ける
- **コードの分割**: 1ファイル200行を超える場合は、機能ごとにファイルを分割すること
- **コメント**: 日本語で簡潔に記述し、コードの意図や複雑なロジックを説明するために使用する。冗長なコメントは避けること。
- **HTML**: HTMLはセマンティックなタグを使用し、ARIA属性も適切に使用する

## アンチパターン
- **グローバル変数**: グローバルスコープに変数を定義しない
- **直接DOM操作**: Reactの仮想DOMをバイパスする直接的なDOM操作は避ける
- **副作用のあるコード**: コンポーネントのレンダリング中に副作用を引き起こすコードは避ける（例: API呼び出し、状態の変更）
- **複雑なロジック**: 単一の関数やコンポーネントに複雑なロジックを詰め込まない
- **無意味な命名**: 意味のない変数名や関数名を避ける（例: `data`, `temp`, `handleClick1`）
