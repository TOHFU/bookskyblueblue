# アーキテクチャ・ディレクトリ構成

## アーキテクチャ

- クリーンアーキテクチャをベースに、プレゼンテーション層、ドメイン層、データ層の3層構造を採用する
- プレゼンテーション層はReactコンポーネントで構成し、UIの実装とユーザーインタラクションを担当する
- ドメイン層はビジネスロジックを担当し、ユースケースやサービスクラスを配置する
- データ層はAPI通信やIndexedDBなどのデータ管理を担当し、リポジトリパターンを採用してデータアクセスを抽象化する
- 状態管理は必要に応じてReactの`useState`や`useReducer`を使用する

## mcpの使用

- AIによるコードの生成のために、以下のMCP（Model Code Prompt）を使用する。必要に応じて利用する。
  - Framelink_Figma_MCP
  - chakra-ui
  - next-devtools
  - playwright

## 作品一覧データ

作品検索のための作品一覧データは、作品ID、作品名、サブタイトル、オリジナルタイトル、著者名、底本初版発行年、文字遣い種別、底本親本出版社、底本名、本文の内容などの情報を含む。これらの情報はJSON形式で保持し、必要に応じてAPIでフロントエンドに提供される。作品データはドメイン層のエンティティとして定義し、データ層のリポジトリを通じてアクセスするようにする。

## 作品データ(本文)

作品本文のデータは、青空文庫のホームページからXTML形式で取得し、IndexedDBに保存する形で管理する。

## ディレクトリ構成

```
src/
├── components/       # プレゼンテーション層のReactコンポーネント
├── domain/           # ドメイン層のビジネスロジック（ユースケース、サービスクラス）
├── data/             # データ層のAPI通信やIndexedDB管理
├── hooks/            # カスタムフック
├── utils/            # ユーティリティ関数
├── styles/           # グローバルスタイルやテーマ
├── assets/           # 画像やフォントなどの静的資産
├── pages/            # Next.jsのページコンポーネント
└── index.tsx         # エントリーポイント
```

- 各層は明確に分離され、依存関係は一方向（プレゼンテーション層 → ドメイン層 → データ層）であることを保証する
- コンポーネントは可能な限り再利用可能な形で設計し、必要に応じてサブディレクトリで整理する
- ドメイン層のユースケースやサービスクラスは、機能ごとにサブディレクトリで整理することも検討する
- データ層のAPI通信やIndexedDB管理は、機能ごとにサブディレクトリで整理することも検討する
